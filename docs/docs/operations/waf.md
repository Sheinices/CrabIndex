# WAF: фильтр запросов

Встроенный WAF (Web Application Firewall) видит каждый HTTP-запрос к CrabIndex: собирает статистику, кто и куда ходит, и блокирует нежелательных клиентов. Управление - в админ-панели, раздел **WAF** (см. [Админ-панель](../admin.md)).

## Что умеет

| Функция | Как работает |
| --- | --- |
| Статистика и журнал | Каждый запрос записывается: время, IP, метод, путь (без query-строки), код ответа, время ответа, User-Agent, хост запроса (Host), сайт-источник (Origin), причина блокировки |
| Чёрный список | IP-адреса и подсети (IPv4 и IPv6, CIDR). Ответ `403 Forbidden` на любой запрос |
| Белый список | Адреса и подсети, на которые не действуют лимиты, баны, ловушки и фильтр User-Agent |
| Лимит запросов | Больше `perMinute` запросов за скользящую минуту с одного IP: ответ `429` и автоматический бан на `banMinutes` |
| Ловушки | Обращение к пути-приманке для сканеров (`/.env`, `/wp-admin`, `/.git/` …): ответ `404` и бан на `trapBanMinutes` |
| Фильтр User-Agent | Регулярные выражения (без учёта регистра). Совпадение: `403` и бан на `banMinutes` |
| Временные баны | Автоматические и ручные, со сроком. Истекают сами |
| Блокировка доменов | Запросы, пришедшие со сторонних сайтов (заголовки `Origin` / `Referer`): встроенный список, чёрный и белый списки доменов, режим «только разрешённые домены». См. [Блокировка доменов](#блокировка-доменов) |
| Боты | Распознавание ботов по User-Agent (встроенный каталог по категориям), статистика по каждому боту, блокировка категорий и отдельных ботов, `robots.txt` с запретом индексации. См. [Боты](#боты) |

## Порядок проверки

Для каждого запроса по очереди:

1. **Localhost** (`127.0.0.0/8`, `::1`) пропускается всегда - от него работает cron и локальные утилиты.
2. **Встроенный список заблокированных доменов** - `403`. Действует на всех, кроме localhost: и на белый список IP, и на локальную сеть.
3. **Локальная сеть** при `whitelistLan: true` и **белый список IP** - пропустить, дальше не проверять.
4. **Чёрный список IP или активный бан** - `403`.
5. **Чёрный список доменов** - `403`. При `domainAllowlistOnly: true` также `403` для запроса с доменом, которого нет в белом списке доменов и который не совпадает с адресом самого сервера.
6. **Белый список доменов** - дальнейшие проверки (боты, User-Agent, ловушки, лимит) не выполняются.
7. **Правила ботов** - заблокированная категория или совпадение с `botBlocked`, если бот не в `botAllowed`: `403` (причина `bot`), без бана.
8. **User-Agent** из `blockUserAgents` - `403` и бан.
9. **Путь-ловушка** из `trapPaths` (сравнение по началу пути, без учёта регистра) - `404` и бан.
10. **Лимит запросов** превышен - `429` с заголовком `Retry-After` и бан.

За блокировку по домену (шаги 2 и 5) и по правилам ботов (шаг 7) IP не банится: одним и тем же сайтом пользуется много людей, а с одного адреса могут ходить и бот, и обычные клиенты.

При `waf.enable: false` не блокируется ничего (в том числе боты), статистика продолжает собираться.

:::note[Примечание]
Реальный IP клиента за обратным прокси берётся из `X-Forwarded-For` (а также `X-Real-IP`, `CF-Connecting-IP`) **только** если прокси работает на том же хосте и подключается с loopback. Если прокси на другой машине, WAF увидит адрес прокси - все клиенты будут для него одним IP. Держите прокси на том же сервере. См. [Обратный прокси](../deployment/reverse-proxy.md).
:::

## Настройки

Секция `waf` в `init.yaml` (её же можно менять в админ-панели: **Настройки → WAF**):

```yaml
waf:
  enable: true               # false - ничего не блокировать (статистика продолжает собираться)
  logRequests: true          # журнал и статистика в памяти
  historySize: 5000          # сколько последних запросов хранить в журнале
  rateLimit:
    enable: true
    perMinute: 300           # запросов с одного IP за минуту
    banMinutes: 15           # бан за превышение (и за User-Agent)
  trapPaths:                 # приманки для сканеров
    - /.env
    - /wp-admin
    - /wp-login.php
    - /.git/
    - /phpmyadmin
  trapBanMinutes: 1440       # бан за ловушку, минут
  blockUserAgents: []        # например ["sqlmap", "nikto", "masscan"]
  whitelistLan: true         # локальная сеть без лимитов и банов
  domainAllowlistOnly: false # true - только домены из белого списка (и сам сервер)
```

:::tip[Совет]
Клиенты вроде Prisma и Lampa делают по несколько запросов на одну карточку. Значение `perMinute: 300` оставляет большой запас для обычного использования. Если у вас много пользователей за одним NAT, поднимите лимит или добавьте их адрес в белый список.
:::

## Списки и баны

Чёрный и белый списки IP и доменов и активные баны хранятся отдельно от конфига - в файле `Data/waf.json` - и переживают перезапуск. Правка из админ-панели не переписывает `init.yaml`.

```json
{
  "blacklist": [{ "value": "203.0.113.0/24", "comment": "сканер", "created": "…", "expires": null }],
  "whitelist": [{ "value": "198.51.100.10", "comment": "офис", "created": "…", "expires": null }],
  "bans":      [{ "ip": "192.0.2.10", "reason": "rate", "created": "…", "expires": "…" }],
  "domainBlacklist": [{ "value": "spam.example", "comment": "чужой парсер", "created": "…", "expires": null }],
  "domainWhitelist": [{ "value": "my-lampa.example", "comment": "своя Lampa", "created": "…", "expires": null }],
  "botBlockCategories": ["ai", "seo"],
  "botBlocked": [{ "value": "MyScraper", "comment": "чужой парсер", "created": "…", "expires": null }],
  "botAllowed": [{ "value": "UptimeRobot", "comment": "свой мониторинг", "created": "…", "expires": null }],
  "robotsDisallow": false
}
```

Списки доменов и правила ботов необязательны: файл без них (от прежних версий) читается как раньше.

Причины банов: `rate` - лимит запросов, `trap` - ловушка, `ua` - User-Agent, `manual` - вручную из панели. Причины блокировки `domain` (домен) и `bot` (бот) в журнале есть, а банов с ними не бывает.

## Блокировка доменов

Браузерные клиенты (веб-версии Lampa и подобные сайты) при обращении к CrabIndex присылают адрес сайта, с которого сделан запрос. По нему WAF может отказать запросам со сторонних сайтов.

### Как определяется домен

- Берётся хост из заголовка `Origin`; если его нет (или он `null`) - хост из `Referer`.
- Хост нормализуется: нижний регистр, без схемы, порта, пути и точки в конце. Международные домены (IDN) сравниваются как есть, без перевода в punycode.
- Правило `example.com` действует на сам `example.com` и на все поддомены `*.example.com`. Сравнение идёт по границе метки: `notexample.com` под правило **не** попадает.
- Запросы без `Origin` и `Referer` (Jackett, Prowlarr, curl, приложения) по домену не блокируются никогда.

### Встроенный список

Эти домены зашиты в программу и блокируются всегда (`403`, причина `domain`) - для всех клиентов, кроме localhost, в том числе для IP из белого списка и локальной сети:

`ndst.pw`, `diskstation.me`, `krilzov.it`, `myds.me`, `lampa.stream`, `bylampa.online`, `abhq.ru`, `abmsx.tech`, `akter.black`, `lampa.click`, `lampa.land`, `lampa1.ru`, `line.pm`, `nnmtv.pw`, `tvigl.info`, `uspeh.sbs`, `usph.xyz`, `xabb.ru`, `lampaua.mooo.com`

:::warning[Внимание]
Встроенный список нельзя изменить, отключить или обойти через админ-панель, `Data/waf.json` или `init.yaml`: добавить такой домен (или его поддомен) в белый список доменов нельзя, удалить из списка - тоже. Изменить его можно только правкой исходного кода (`crates/crabindex/src/waf/domains.rs`) и пересборкой.
:::

### Чёрный и белый списки доменов

Управляются на вкладке **WAF → Правила → Домены** (или через API ниже). Записи устроены как у списков IP: комментарий и необязательный срок действия. При добавлении можно вставить адрес целиком - схема, порт, путь и префикс `*.` отбрасываются; домен должен состоять из букв, цифр, дефисов и точек, содержать хотя бы одну точку и быть не длиннее 253 символов.

- **Чёрный список доменов** - `403`. Проверяется после чёрного списка IP и банов; IP из белого списка его не проходят.
- **Белый список доменов** - запросы с этих доменов не проверяются лимитом запросов, фильтром User-Agent и ловушками. Встроенный список, чёрный список IP и баны он не отменяет.

### Режим «только разрешённые домены»

При `domainAllowlistOnly: true` (**Настройки → WAF**) запрос, у которого есть `Origin`/`Referer`, пропускается, только если его домен есть в белом списке доменов или совпадает с адресом самого сервера (заголовок `Host` запроса - так продолжает работать собственный веб-интерфейс CrabIndex). Всё остальное с доменом получает `403`. Запросы без `Origin` и `Referer` проходят как обычно. Если белый список доменов пуст, проверка настроек предупредит об этом.

## Хосты запросов

Кроме сайта-источника (`Origin`) WAF запоминает, на какой адрес сервера обращался клиент - хост из заголовка `Host`. Он нормализуется так же, как домен: нижний регистр, без порта. Запрос на голый IP показывается как IP, запрос без `Host` - как `-`.

По этой статистике видно, кто ходит на ваш основной домен (например, `sync.example.com`), кто стучится напрямую по IP (обычно сканеры) и какие чужие домены направлены на ваш сервер. Хост только записывается и ни на что не влияет: блокировки по нему нет.

## Боты

Вкладка **WAF → Боты** показывает автоматических клиентов и позволяет их отключить, чтобы они не нагружали сервер.

### Как распознаются боты

Бот определяется по заголовку `User-Agent`: сначала по встроенному каталогу сигнатур (подстрока без учёта регистра, побеждает первое совпадение), затем по общему признаку. Результат кэшируется по строке User-Agent.

| Категория | `id` | Примеры |
| --- | --- | --- |
| Поисковые роботы | `search` | Googlebot, bingbot, YandexBot, YandexImages, Baiduspider, DuckDuckBot, Applebot, Sogou, Exabot, SeznamBot, PetalBot |
| AI-краулеры | `ai` | GPTBot, ChatGPT-User, OAI-SearchBot, ClaudeBot, Claude-Web, anthropic-ai, CCBot, Bytespider, PerplexityBot, Google-Extended, Amazonbot, cohere-ai, Diffbot, ImagesiftBot, meta-externalagent, FacebookBot |
| SEO-сервисы | `seo` | AhrefsBot, SemrushBot, MJ12bot, DotBot, BLEXBot, DataForSeoBot, serpstatbot, Barkrowler, SeekportBot, MegaIndex, Screaming Frog, rogerbot |
| Соцсети и мессенджеры | `social` | facebookexternalhit, Twitterbot, TelegramBot, WhatsApp, Discordbot, Slackbot, LinkedInBot, vkShare, SkypeUriPreview |
| Мониторинг доступности | `monitoring` | UptimeRobot, Pingdom, StatusCake, Better Uptime, Site24x7, Datadog, HetrixTools |
| Сканеры уязвимостей | `scanners` | zgrab, masscan, Nmap, Nuclei, sqlmap, Nikto, Censys, CensysInspect, Expanse (Palo Alto Networks), InternetMeasurement, ModatScanner, l9explore, httpx, fasthttp, WPScan |
| HTTP-библиотеки и утилиты | `libraries` | python-requests, python-urllib, python-httpx, aiohttp, Go-http-client, curl, Wget, okhttp, Java, Apache-HttpClient, node-fetch, axios, libwww-perl, PHP, Scrapy, HeadlessChrome |
| Пустой User-Agent | `empty` | Запросы без заголовка `User-Agent` |
| Прочие боты | `other` | User-Agent со словами `bot`, `crawler`, `crawl`, `spider`, `slurp`, которых нет в каталоге. Имя бота - название продукта из User-Agent (`FooBot/1.2` → `FooBot`) |

Клиенты синхронизации и медиа-приложения (CrabIndex, Jackett, Prowlarr, Prisma, Lampa, Kodi, обычные браузеры) в каталог не входят и ботами не считаются.

### Статистика

Для каждого бота: запросы, заблокировано, время последнего запроса, число разных IP, самые частые пути и несколько примеров User-Agent. Для категорий - суммарные запросы и блокировки. Статистика ботов, как и остальная, хранится в памяти, собирается при `logRequests: true` и сбрасывается кнопкой **Сбросить статистику**.

### Правила

По умолчанию ничего не блокируется. Правила хранятся в `Data/waf.json`:

- `botBlockCategories` - категории, заблокированные целиком (переключатель **Блокировать всю категорию** на карточке категории).
- `botBlocked` - отдельные боты: имя из каталога (или из таблицы замеченных ботов) либо любая часть User-Agent, от 3 до 128 символов, без учёта регистра.
- `botAllowed` - части User-Agent (или имена ботов), которые не блокируются никогда: важнее и `botBlocked`, и заблокированных категорий.

Записи `botBlocked` и `botAllowed` устроены как у других списков: комментарий и необязательный срок действия. Одно и то же значение не может быть сразу в обоих списках: добавление в один список убирает его из другого.

Блокировка отвечает `403 Forbidden` с причиной `bot` и не банит IP. На localhost, локальную сеть (`whitelistLan`), белый список IP и белый список доменов правила ботов не действуют, а чёрные списки IP и доменов и баны проверяются раньше.

:::warning[Внимание]
Категория **HTTP-библиотеки и утилиты** (curl, python-requests, Go, okhttp …) и **Пустой User-Agent** задевают и легитимных клиентов: ваши скрипты, cron-задачи на другой машине, некоторые приложения. Блокировка **Поисковых роботов** убирает сервер из поисковиков. Если нужно заблокировать категорию, но оставить своего клиента, добавьте его User-Agent в разрешённые боты.
:::

### robots.txt

Флаг `robotsDisallow` (переключатель **robots.txt: запретить индексацию**) заставляет CrabIndex отвечать на `GET /robots.txt` так:

```
User-agent: *
Disallow: /
```

Вежливые краулеры после этого перестают заходить. Файл отдаётся и ботам, заблокированным правилами ботов, чтобы они узнали о запрете. Когда флаг выключен (по умолчанию), `/robots.txt` отдаётся как раньше - файлом веб-интерфейса из `wwwroot/` (при `web: true`).

## Раздел WAF в админ-панели

- **Обзор** - всего запросов, заблокировано, уникальных IP, запросов в секунду за 60 минут или 24 часа; график запросов и блокировок; коды ответов; причины блокировок; топ IP, сайтов-источников (Origin), путей и доменов запросов (Host).
- **Журнал** - последние запросы с хостом (Host) и сайтом-источником (Origin) и фильтрами по IP (адрес, подсеть или часть адреса), пути, сайту-источнику, хосту, коду ответа, только заблокированные.
- **IP-адреса** - таблица клиентов со статусом и действиями: заблокировать, в белый список, бан на 15 минут / час / сутки / свой срок, снять бан, показать запросы.
- **Правила** - управление чёрным и белым списками IP, раздел **Домены** (встроенный список только для просмотра, чёрный и белый списки доменов, состояние `domainAllowlistOnly`), активные баны, текущие настройки, сброс статистики.
- **Боты** - карточки категорий с запросами, блокировками и переключателем блокировки всей категории, таблица замеченных ботов (запросы, блокировки, IP, пути, статус) с действиями «Блокировать», «Разрешить», «Снять правило», свои правила по User-Agent и переключатель `robots.txt`.

На главном экране панели есть карточка WAF с запросами и блокировками за последний час.

## Защита от самоблокировки

Сервер не даст добавить в чёрный список или забанить адрес или подсеть, в которую входит ваш текущий IP, а также loopback (`127.0.0.0/8`, `::1`, `0.0.0.0/0`, `::/0`). Ваш IP показан на вкладке **Правила**. Даже если доступ всё же потерян, с самого сервера CrabIndex доступен всегда (localhost не блокируется), а список можно поправить в `Data/waf.json` и перезапустить сервис.

## Ограничения

- Статистика и журнал хранятся в памяти и обнуляются при перезапуске.
- Число отслеживаемых IP, путей, доменов, хостов и ботов ограничено (старые вытесняются), журнал - последними `historySize` запросами.
- Строка запроса (`?…`) в журнал не пишется; токен админ-панели никогда не сохраняется.
- WAF - защита уровня приложения. От объёмных DDoS-атак нужен внешний фильтр (провайдер, Cloudflare).

## Админ API

Все маршруты - под `{admin.path}/api/waf/…` с сессией админ-панели и заголовком `X-Crab-Admin: 1` (см. [Админ-панель](../admin.md)).

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `waf/overview?window=60m\|24h` | Итоги, график, `blockedByReason` (включая `domain` и `bot`), топы, `topOrigins: [{origin, requests, blocked}]` и `topHosts: [{host, requests, blocked}]` (до 20) |
| GET | `waf/requests?ip=&path=&origin=&host=&status=&blocked=&limit=` | Журнал запросов; у записи есть `origin` (домен или `null`) и `host` (хост запроса или `-`), `origin=` и `host=` - фильтры по подстроке, `blocked=domain` / `blocked=bot` - блокировки по домену / правилам ботов |
| GET | `waf/ips?sort=requests\|blocked\|lastSeen&limit=` | Клиенты и их статус |
| GET | `waf/rules` | Списки IP, баны, `domainBlacklist`, `domainWhitelist`, `builtinDomains` (встроенный список), настройки и ваш IP (`you`) |
| POST | `waf/rules` | Добавить: `{"list":"blacklist","value":"203.0.113.0/24","comment":"…","expiresMinutes":60}`; `list` - `blacklist`, `whitelist`, `domainBlacklist` или `domainWhitelist` |
| DELETE | `waf/rules?list=…&value=…` | Удалить запись |
| POST | `waf/ban` | Забанить: `{"ip":"192.0.2.10","minutes":30}` |
| DELETE | `waf/ban?ip=…` | Снять бан |
| POST | `waf/reset` | Сбросить статистику |
| GET | `waf/bots` | `categories: [{id, label, description, requests, blocked, blockedCategory, botCount}]`, `bots: [{name, category, requests, blocked, lastSeen, ips, topPaths, samples, status}]` (`status` - `blocked`, `allowed` или `seen`), `rules: {botBlockCategories, botBlocked, botAllowed, robotsDisallow}`, `catalog: {категория: [имена]}` |
| POST | `waf/bots/category` | Заблокировать или разблокировать категорию: `{"id":"seo","block":true}` |
| POST | `waf/bots/rules` | Добавить правило: `{"list":"botBlocked","value":"MyScraper","comment":"…","expiresMinutes":60}`; `list` - `botBlocked` или `botAllowed` |
| DELETE | `waf/bots/rules?list=…&value=…` | Удалить правило (без учёта регистра) |
| POST | `waf/bots/robots` | `robots.txt` с запретом индексации: `{"disallow":true}` |

Встроенный список защищён и в API: домен из него (или его поддомен) в `domainWhitelist` - ответ `400` с `{"ok":false,"error":"… заблокирован встроенным списком и не может быть разрешён"}`; в `domainBlacklist` - `400` (домен уже заблокирован); `DELETE` встроенного домена - тоже `400`.
