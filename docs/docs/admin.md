# Админ-панель

Админ-панель - отдельное веб-приложение для управления сервером: настройки, ручной запуск парсеров, фоновые задачи, обслуживание FileDB и просмотр логов. Публичный сайт (`/` и `/stats`) ничего этого не умеет и доступа к настройкам не даёт.

Панель лежит в `wwwroot/admin/`, но как обычная статика не раздаётся: сервер отдаёт её только под закрытым адресом и только после проверки доступа.

## Как войти

Нужны две вещи:

1. **Адрес входа** вида `http://<сервер>:9117/admin?<токен>`.
2. **Пароль** - значение `devkey` из конфигурации.

Откройте адрес входа в браузере. Сервер запомнит браузер (cookie) и перенаправит на `/admin/`, где попросит ввести ключ. После входа откроется панель.

### Где взять адрес и пароль

При первом запуске, если `admin.token` или `devkey` пусты, сервер сам генерирует недостающие значения, записывает их в рабочий конфиг (`init.yaml` или `init.conf`) и один раз выводит в лог:

```text
[warn] admin: generated admin credentials in init.yaml
[warn] admin: http://192.168.1.10:9117/admin?Z0mt0N7r2hoUM2TuOk
[warn] admin: devkey: 9fQ2…
```

- **Установщик** `scripts/install.sh` генерирует токен и `devkey` сам и печатает их в конце установки - см. [Установка](installation.md).
- **Docker**: `docker logs crabindex 2>&1 | grep 'admin:'`. В контейнере вместо адреса сервера выводится `<host>` - подставьте адрес хоста.
- **В любой момент** адрес и ключ выводит команда `crabindex admin`, запущенная из рабочего каталога:

```bash
cd /opt/crabindex && sudo -u crabindex ./crabindex admin
docker exec crabindex ./crabindex admin
```

```text
admin: http://192.168.1.10:9117/admin?Z0mt0N7r2hoUM2TuOk
admin: devkey: 9fQ2…
```

Команда читает конфиг и сразу завершается; сервер при этом не запускается. Если значения ещё не сгенерированы, она сообщит об этом и завершится с кодом `1`.

:::note[Примечание]
Адрес в логе строится из `listenip` и `listenport`. При `listenip: any` подставляется основной IP машины. Если панель открывается через обратный прокси, используйте свой домен: `https://crabindex.example.com/admin?<токен>`.
:::

:::note[Примечание]
При генерации сервер перезаписывает конфиг целиком, поэтому комментарии в `init.yaml` пропадают. Установщик `scripts/install.sh` вписывает значения точечно и комментарии сохраняет.
:::

## Три уровня защиты

| Уровень | Настройка | Что даёт |
| --- | --- | --- |
| 1. Свой путь | `admin.path`, по умолчанию `/admin` | Панель не лежит по предсказуемому адресу |
| 2. Токен в адресе | `admin.token` | Без токена сервер не показывает даже страницу входа |
| 3. Пароль | `devkey` | Вход в панель и доступ к её API |

**Путь и токен** прячут сам факт наличия панели. Пока в браузере нет cookie с правильным токеном, любой запрос к `{admin.path}` и `{admin.path}/*` получает ровно тот же ответ, что и несуществующий адрес: `404` (или `401`, если задан `apikey`). Сканер или случайный посетитель не отличит панель от пустого места и не сможет подбирать пароль: форма входа ему просто не отдаётся.

**Пароль** защищает на случай, если адрес с токеном утёк: например, остался в истории браузера или в логах прокси. Без `devkey` панель покажет только форму входа.

Как это устроено:

- `GET {admin.path}?{токен}` (или `?token={токен}`) ставит cookie `crab_gate` и перенаправляет на `{admin.path}/`. В cookie лежит не токен, а его HMAC с секретом этой установки (`Data/temp/admin.secret`). Cookie живёт 30 дней.
- Вход ключом (`POST {admin.path}/api/login`) создаёт сессию и ставит cookie `crab_session`. Срок жизни сессии задаёт `admin.sessionHours` (по умолчанию 12 часов). Сессии хранятся в памяти процесса.
- Обе cookie имеют флаги `HttpOnly` и `SameSite=Strict`, а область действия `Path` ограничена `{admin.path}`. Флаг `Secure` ставится, если запрос пришёл по HTTPS, в том числе через обратный прокси на том же хосте с `X-Forwarded-Proto: https`.
- Изменяющие запросы к API панели (`POST` и т. п.) должны содержать заголовок `X-Crab-Admin: 1`, иначе ответ `403`. Запросы с других сайтов (`Sec-Fetch-Site: cross-site` или `same-site`) отклоняются с `403`. Это защита от CSRF.
- С одного IP допускается не больше 5 неудачных попыток входа за 10 минут. Дальше сервер отвечает `429 Too Many Requests` с `Retry-After: 600`. Каждая неудачная попытка пишется в лог (`admin: login failed from …`).
- Ответы панели не кешируются (`Cache-Control: no-store`), не передают `Referer` и помечены `X-Robots-Tag: noindex, nofollow`.

После перезапуска сервера сессии сбрасываются, и ключ нужно ввести заново. Cookie `crab_gate` переживает перезапуск, пока не изменились токен, путь и файл `Data/temp/admin.secret`. Поэтому заново открывать адрес с токеном не нужно.

## Настройки

Блок `admin` в `init.yaml`:

```yaml
devkey: "9fQ2…"            # пароль панели (и ключ для /cron, /dev, /jsondb извне)

admin:
  enable: true            # false - панель недоступна (404)
  path: /admin            # один сегмент [a-z0-9_-], 2-32 символа
  token: "Z0mt0N7r2hoUM2TuOk"   # [A-Za-z0-9], 12-64 символа
  sessionHours: 12        # время жизни сессии после входа, 1-8760
```

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `admin.enable` | `true` | Выключенная панель отвечает как несуществующий адрес |
| `admin.path` | `/admin` | Префикс адреса панели. Принимается `name`, `/name` или `/name/`. Нельзя использовать служебные пути: `/`, `/api`, `/cron`, `/dev`, `/docs`, `/swagger`, `/sync`, `/stats`, `/torznab`, `/health`, `/version`, `/lastupdatedb`, `/jsondb`, `/img`, `/assets`, `/search`, `/openapi.yaml`, `/opensearch.xml`, `/sw.js`, `/manifest.webmanifest` |
| `admin.token` | пусто → генерируется | Токен в адресе входа. Сгенерированный токен состоит из 18 символов |
| `admin.sessionHours` | `12` | Сколько часов действует вход |
| `devkey` | пусто → генерируется | Пароль панели, сгенерированный - из 32 символов. Тот же ключ открывает `/cron/*`, `/dev/*`, `/jsondb*` извне, см. [Аутентификация](authentication.md) |

Если `admin.path` в файле недопустим, сервер пишет предупреждение и использует `/admin`. Сохранить такой путь из панели нельзя: проверка конфигурации вернёт ошибку.

Путь при первой генерации можно задать переменной окружения `CRABINDEX_ADMIN_PATH` (например, `CRABINDEX_ADMIN_PATH=/my-panel`). Переменная учитывается только в момент генерации токена и `devkey`, то есть на свежей установке. Дальше путь берётся из конфига.

## Смена пути, токена и ключа

Менять значения можно двумя способами:

- **в панели**: **Настройки → группа «Админ-панель»** (`devkey` - в группе «Сервер»). После сохранения панель покажет новый адрес входа с кнопкой копирования;
- **в `init.yaml`**: сервер перечитает файл в течение ~10 секунд, перезапуск не нужен.

Что происходит после смены:

| Что изменили | Последствия |
| --- | --- |
| `admin.path` | Старый адрес перестаёт работать сразу. Обе cookie привязаны к старому пути, поэтому откройте новый адрес с токеном и войдите заново |
| `admin.token` | Cookie `crab_gate` во всех браузерах становятся недействительными: откройте адрес с новым токеном. Если сессия ещё жива, вводить ключ заново не придётся |
| `devkey` | Все сессии, включая текущую, завершаются сразу. Войдите с новым ключом. Новый ключ нужен и для `/cron/*`, `/dev/*`, `/jsondb*` извне, в том числе в cron-заданиях, если они передают `devkey` |
| `admin.enable: false` | Панель исчезает. Вернуть её можно только правкой `init.yaml` |
| удалён `Data/temp/admin.secret` | Файл создаётся заново, все cookie `crab_gate` становятся недействительными |

Чтобы выгнать всех, кто сейчас в панели, и закрыть утёкший адрес, смените одновременно `admin.token` и `devkey`.

:::warning[Внимание]
Не оставляйте `admin.token` или `devkey` пустыми. С пустым токеном панель недоступна до перезапуска, а с пустым `devkey` вход невозможен. При следующем старте сервер снова сгенерирует пустые значения и выведет их в лог.
:::

Сгенерировать новые значения вручную:

```bash
openssl rand -base64 48 | tr -dc 'A-Za-z0-9' | head -c 18; echo   # admin.token
openssl rand -base64 48 | tr -dc 'A-Za-z0-9' | head -c 32; echo   # devkey
```

## Разделы панели

| Раздел | Что делает |
| --- | --- |
| **Обзор** | Версия, аптайм, адрес прослушивания, число раздач и ключей FileDB, время последнего обновления базы, активные фоновые задачи, состояние синхронизации (`syncapi`, последняя синхронизация), список трекеров, путь и формат конфига. Обновляется каждые 10 секунд |
| **Трекеры** | Все трекеры с признаком «включён» и состоянием ParseAll. Ручной запуск cron-действий трекера (`parse`, `UpdateTasksParse`, `ParseAllTask`, последние страницы, backfill и т. д.) с параметрами. Ответ сервера показывается во всплывающем окне. Отсюда же открывается лог трекера |
| **Задачи** | Фоновые задачи процесса (`/health/background-jobs`) и состояние циклов ParseAll на диске, кнопка «Возобновить ParseAll», автообновление |
| **Настройки** | Редактор конфигурации: форма по схеме полей или текст YAML/JSON, проверка, diff перед сохранением, атомарное сохранение и мгновенное применение. См. [Config API](api-reference/config.md) |
| **Обслуживание** | Проверка FileDB (режимы «Отчёт», «Безопасное исправление», «Полное исправление»), сохранение базы на диск (`jsondb/save`), прогрев Cloudflare, диагностика только для чтения и миграции данных. См. [Обслуживание FileDB](operations/maintenance.md) |
| **Логи** | Файлы `Data/log/*.log`: последние N строк (по умолчанию 300, максимум 5000), поиск по тексту, фильтр совпадений, автообновление |
| **WAF** | Статистика запросов, журнал, клиенты по IP, чёрный и белый списки IP и доменов, баны. Подробно — [WAF: фильтр запросов](operations/waf.md) |

Кнопка выхода завершает сессию на сервере. Тема (светлая или тёмная) переключается в шапке.

:::warning[Внимание]
Миграции и «исправляющие» режимы проверки меняют базу. Перед запуском сделайте резервную копию `Data/fdb` и `Data/masterDb.bz`.
:::

## API панели

Интерфейс панели работает через собственный API под `{admin.path}/api/`. Доступ к нему требует cookie `crab_gate`, а все маршруты, кроме `session`, `login` и `logout`, - ещё и сессию. Без сессии ответ `401 {"error":"unauthorized"}`.

| Маршрут | Описание |
| --- | --- |
| `GET session` | `{"authenticated": bool, "version": "…", "loginEnabled": bool}`; `loginEnabled` равен `false`, если `devkey` пуст |
| `POST login` | Тело `{"devkey": "…"}`. Успех: `{"ok": true}` и cookie сессии. Ошибки: `401 invalid key`, `429 too many attempts` |
| `POST logout` | Завершает сессию |
| `GET overview` | Сводка для раздела «Обзор» |
| `GET logs` | Список `[{"name", "size", "modified"}]` файлов `Data/log/*.log` |
| `GET logs/{имя}?lines=N` | Последние `N` строк файла (1-5000, по умолчанию 300): `{"name", "lines": [...]}` |
| `config`, `config/*` | [Config API](api-reference/config.md) |
| `cron/*` | [Cron API](api-reference/cron.md), например `cron/rutor/parse` |
| `dev/*` | [Dev API](api-reference/dev.md) |
| `jsondb`, `jsondb/*` | Сохранение FileDB, например `jsondb/save` |
| `stats/*` | [Статистика](api-reference/stats.md) |
| `health/background-jobs` | Активные фоновые задачи |

Запросы к `cron/*`, `dev/*`, `jsondb*` и `stats/*` через панель не требуют ни `devkey`, ни `apikey`: их заменяет сессия. Для автоматизации (cron, скрипты) по-прежнему удобнее вызывать `/cron/*` напрямую с `devkey`, см. [Cron](deployment/cron.md).

Пример работы с API панели из командной строки:

```bash
BASE=https://crabindex.example.com/admin
curl -s -c jar -b jar -o /dev/null "$BASE?ТОКЕН"                  # cookie crab_gate
curl -s -c jar -b jar -H 'X-Crab-Admin: 1' -H 'Content-Type: application/json' \
  -d '{"devkey":"DEVKEY"}' "$BASE/api/login"                      # cookie crab_session
curl -s -b jar "$BASE/api/overview"
curl -s -b jar "$BASE/api/config?format=yaml"
```

## Рекомендации по безопасности

- **Публикуйте панель только по HTTPS.** Ставьте CrabIndex за [обратный прокси](deployment/reverse-proxy.md) с TLS. По HTTP токен в адресе и ключ при входе идут открытым текстом, а cookie не получают флаг `Secure`.
- **Не делитесь адресом входа.** Токен в адресе - такой же секрет, как пароль. Не отправляйте его в чаты и не публикуйте скриншоты. Помните, что адрес с токеном остаётся в истории браузера и может попасть в журнал обратного прокси.
- **Выберите свой путь** вместо `/admin`: установщик предлагает это при установке.
- **Меняйте токен** (и `devkey`), если адрес мог утечь, а также периодически.
- **Отключите панель** (`admin.enable: false`), если она не нужна: например, на узле, которым управляют только через `init.yaml`.
- Не используйте `devkey` как `apikey`: поисковый ключ раздаётся клиентам (Lampa, Sonarr), а `devkey` открывает управление сервером.

## Решение проблем

**`404` на `/admin` (или на своём пути).** Сервер не видит действующей cookie `crab_gate`, и панель прикидывается несуществующим адресом. Возможные причины:

- адрес открыт без токена или с неверным токеном. Откройте полный адрес `…/admin?ТОКЕН`;
- путь или токен изменены. Возьмите актуальный адрес командой `crabindex admin`;
- `admin.enable: false`;
- токен в конфиге пуст (сервер ещё не перезапускался после очистки) или содержит недопустимые символы;
- обратный прокси отбрасывает строку запроса или cookie, либо публикует только часть путей. Проверьте, что `{admin.path}` и `{admin.path}/*` проксируются целиком.

Если задан `apikey`, вместо `404` придёт `401`: так сервер отвечает на любой незнакомый адрес.

**`503 admin UI is not built`.** Токен принят, но нет `wwwroot/admin/index.html`. Соберите интерфейс (`make web`) или используйте бандл `make dist` либо Docker-образ.

**Форма входа пишет «Неверный ключ».** Введите значение `devkey` из текущего конфига (`crabindex admin` покажет его). Ключ мог смениться: после смены `devkey` все сессии завершаются.

**`429` / «Слишком много попыток».** С вашего IP было 5 неудачных попыток за 10 минут. Подождите до 10 минут. Лимит считается по IP клиента. Если прокси работает не на том же хосте (например, в другом контейнере) и не передаёт адрес клиента, все посетители выглядят для сервера одним IP и делят один лимит.

**Постоянно выбрасывает на форму входа.** Сессия истекла (`admin.sessionHours`), сервер перезапустили или сменили `devkey`. Войдите снова.

**Потерян адрес или ключ.** Выполните `crabindex admin` в рабочем каталоге (для Docker - `docker exec crabindex ./crabindex admin`) или посмотрите `admin.path`, `admin.token` и `devkey` в `init.yaml`.

**Настройки не сохраняются в Docker.** Проверьте, что том `/app/config` смонтирован и доступен на запись, см. [Docker](deployment/docker.md).
