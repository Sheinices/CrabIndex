# Обзор конфигурации

Вся конфигурация CrabIndex - один файл в **рабочем каталоге** процесса:

1. `init.yaml` - YAML, предпочтительный формат;
2. `init.conf` - JSON.

Если существуют оба файла, используется `init.yaml`. Если нет ни одного, сервер работает на значениях по умолчанию, заданных в коде. Однако при первом запуске он создаёт `init.yaml` со сгенерированными `admin.token` и `devkey` (см. [Админ-панель](../admin.md)).

В файле достаточно указать только ключи, отличающиеся от умолчаний: пользовательский документ накладывается поверх значений по умолчанию.

| Где | Рабочий файл |
| --- | --- |
| Сборка из исходников / systemd | `/opt/crabindex/init.yaml` (рядом с бинарником, `WorkingDirectory`) |
| Docker | Файл в томе `/app/config/init.yaml`; `/app/init.yaml` - символьная ссылка на него |

`Data/example.yaml` (и `Data/example.conf`) - полный пример с комментариями. Это шаблон, сервер его не читает.

## Горячая перезагрузка

Сервер проверяет время изменения `init.yaml` / `init.conf` каждые 10 секунд и при изменении перечитывает файл. Перезапуск не нужен. Применённая конфигурация (с замаскированными секретами) печатается в лог категории `config`. Если файл не парсится, в лог пишется ошибка, а продолжает действовать предыдущая конфигурация.

Порт и адрес прослушивания (`listenip`, `listenport`) применяются только при старте.

## Правила разбора

- Имена ключей и блоков **не чувствительны к регистру**: `Rutor:`, `rutor:` и `RUTOR:` - один и тот же блок.
- Вложенные объекты сливаются по ключам, массивы и скаляры заменяются целиком.
- `null` оставляет значение по умолчанию.
- Строки приводятся к типу поля: `"8"` → `8`, `"yes"`/`"on"`/`"1"` → `true`.
- `init.conf` - JSON, в котором допустимы комментарии `//` и `/* */` (как в `Data/example.conf`).

## Редактирование в админ-панели

Раздел **Настройки** [админ-панели](../admin.md) - редактор с формой, режимом YAML/JSON, валидацией и diff. Сохранение атомарно перезаписывает рабочий файл и сразу применяет настройки. Файл записывается целиком, поэтому комментарии из него пропадают.

:::note[Примечание]
В Docker `/app/init.yaml` - символьная ссылка на `/app/config/init.yaml` в томе, поэтому админ-панель сохраняет изменения прямо туда, и они переживают перезапуск контейнера.
:::

В `Data/example.yaml` поля `cookie` и `login` трекеров пустые, образцы значений даны в комментариях. Заполните их своими данными только для тех трекеров, где нужна авторизация.

## Основные параметры

| Параметр | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `listenip` | string | `any` | Адрес прослушивания. `any` или пусто - все интерфейсы IPv4 (`0.0.0.0`); можно указать `127.0.0.1`, `::` и т. п. |
| `listenport` | int | `9117` | Порт HTTP |
| `apikey` | string | пусто | Ключ поисковых API. Пусто - без проверки. См. [Аутентификация](../authentication.md) |
| `devkey` | string | генерируется | Пароль [админ-панели](../admin.md) и ключ административных путей (`/cron/*`, `/dev/*`, `/jsondb*`) вне локальной сети. Если пуст, при старте генерируется и записывается в конфиг |
| `admin.enable` | bool | `true` | Включить админ-панель |
| `admin.path` | string | `/admin` | Путь админ-панели: один сегмент `[a-z0-9_-]`, 2-32 символа |
| `admin.token` | string | генерируется | Токен в адресе входа `{admin.path}?{admin.token}`, `[A-Za-z0-9]`, 12-64 символа |
| `admin.sessionHours` | int | `12` | Время жизни сессии админ-панели, часы (1-8760) |
| `web` | bool | `true` | Раздавать сайт и статические файлы из `wwwroot/` (админ-панель от этого флага не зависит) |
| `openstats` | bool | `true` | Отдавать данные на `/stats/*` |
| `opensync` | bool | `true` | Отдавать базу другим инстансам через `/sync/*` |
| `mergeduplicates` | bool | `true` | Объединять одинаковые раздачи с разных трекеров |
| `mergenumduplicates` | bool | `true` | То же для запросов клиента NUM |
| `disable_trackers` | list | `[]` | Трекеры, отключённые на этом инстансе |

## FileDB и синхронизация

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `fdbPathLevels` | `2` | Раскладка каталогов `Data/fdb`. Не меняйте после наполнения базы. См. [FileDB](../concepts/filedb.md) |
| `maxreadfile` | `200` | Максимум бакетов, читаемых одним нечётким поиском |
| `evercache.*` | см. [FileDB](../concepts/filedb.md) | Кеш открытых бакетов |
| `logFdb`, `logFdbRetentionDays`, `logFdbMaxSizeMb`, `logFdbMaxFiles` | `true`, `7`, `0`, `0` | Журнал изменений FileDB |
| `syncapi` | не задан | URL сервера синхронизации |
| `synctrackers` | не задан | Какие трекеры принимать при синхронизации; также список трекеров в `/api/v1.0/trackers` и Torznab |
| `syncsport` | `true` | Принимать спортивные раздачи при синхронизации |
| `syncspidr` | `true` | Периодически обновлять сиды/пиры с `syncapi` |
| `timeSync` | `60` | Интервал синхронизации, минуты (минимум 20) |
| `timeSyncSpidr` | `60` | Интервал обновления сидов/пиров, минуты (минимум 20) |
| `saveCheckpointEveryNBatches` | `5` | Сохранять позицию синхронизации каждые N страниц |
| `timeStatsUpdate` | `90` | Интервал сбора статистики, минуты; `-1` - пауза |

См. [Синхронизация](../concepts/sync.md).

## Минимальный init.yaml

```yaml
apikey: "длинная-случайная-строка"
syncapi: https://sync.crab.rip
```

Всё остальное возьмётся из значений по умолчанию, а `devkey` и `admin.token` сервер сгенерирует и допишет в файл при первом запуске.

## Config API

Программно конфигурацию можно читать и менять только через API админ-панели: `{admin.path}/api/config/*`, с cookie сессии панели. Публичного `/api/v1.0/config` больше нет, прямой запрос к нему возвращает `404`. Подробнее - [Config API](../api-reference/config.md).
