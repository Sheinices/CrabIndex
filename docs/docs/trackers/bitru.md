# BitRu

![](/img/trackers/bitru.ico)

BitRu (slug `bitru`) - трекер с официальным JSON API (`api.php?get=torrents`), около 175 тыс. раздач. HTML не разбирается: CrabIndex запрашивает API и для каждой новой раздачи скачивает `.torrent` (`api.php?download=<id>`), из которого строит магнет-ссылку.

Раздачи на BitRu часто обновляются, поэтому используются две задачи: `parse` забирает только самую свежую страницу, а `backfill` постепенно проходит архив вглубь с сохранением курсора между запусками.

## Параметры по умолчанию

| Параметр | Значение |
| --- | --- |
| Блок в `init.yaml` | `Bitru` |
| `host` | `https://bitru.org` (пустой `host` тоже означает этот адрес) |
| `alias` | не используется |
| `reqMinute` / `parseDelay` | не используются: между всеми запросами к API фиксированная пауза 250 мс (лимит API - 5 запросов/с на IP) |
| `useproxy` | `false` (поддерживается) |
| Авторизация | не нужна |
| Кодировка | JSON (UTF-8) |
| Категории | запрашиваются `movie`, `serial`, `video`; из `video` сохраняются только документальное, спорт и шоу |
| Магнет-ссылки | из скачанного `.torrent` |
| Учитывает `disable_trackers` | нет |

## Конфигурация

```yaml
Bitru:
  host: https://bitru.org
  useproxy: false
  log: true
```

## Cron-маршруты

Маршруты принимают `GET` и `POST`, пути и имена параметров регистронезависимы. Все три задачи синхронные и делят одну блокировку: пока выполняется одна, остальные сразу возвращают `work`.

| Маршрут | Параметры | Ответ | Описание |
| --- | --- | --- | --- |
| `/cron/bitru/parse` | `limit` (100, ограничение 1..100) | `saved N`, `no items`, `error: …` или `work` | Одна самая новая страница API |
| `/cron/bitru/backfill` | `pages` (20, ограничение 1..50), `limit` (100, 1..100) | `saved N, fetchedPages=…, committedPages=…, cursor=…[, finished]`, `no items, …`, `finished, …`, `error: …` или `work` | Идёт вглубь архива от сохранённого курсора, до `pages` страниц за запуск |
| `/cron/bitru/ParseFromDate` | `lastnewtor` (обязателен, `dd.MM.yyyy`), `pages` (20, 1..50), `limit` (100, 1..100) | как у `backfill`; `bad lastnewtor (use dd.MM.yyyy)` / `bad date format (use dd.MM.yyyy)` при ошибке | Раздачи старше указанного дня; курсор backfill продвигается так же |

### Как работает курсор backfill

- Курсор - unix-время, хранится в `Data/temp/bitru_backfill_cursor.txt`. Он сдвигается только после того, как страница полностью сохранена.
- Когда API больше не отдаёт следующую страницу, в файл записывается `finished`: проход закончен. Следующий вызов `backfill` начинает новый проход с самой свежей страницы (аналог нового круга ParseAll).
- Чтобы прервать текущий проход и начать сначала, удалите файл курсора.
- Обход останавливается, если страница целиком повторяет предыдущую, API вернул ошибку или пустой список.

:::note[Примечание]
В API BitRu параметр `after_date` на деле означает «старше указанной даты», а `before_date` - «новее», то есть наоборот относительно официального описания. CrabIndex учитывает фактическое поведение.
:::

## Рекомендуемое расписание

```crontab
# Свежая страница - три раза в час
10,30,50 * * * *  /opt/crabindex/Data/run-job.sh bitru-parse http://127.0.0.1:9117/cron/bitru/parse 900

# Архив: pages=20 ≈ до 2000 раздач в час (полный проход ~3,5 дня)
40 * * * *  /opt/crabindex/Data/run-job.sh bitru-backfill "http://127.0.0.1:9117/cron/bitru/backfill?pages=20" 900
```

Не увеличивайте `pages` в расписании: backfill держит ту же блокировку, что и `parse`, и длинный прогон заставит пропустить запуск в `:50`. Разовый `pages=50` для ручной догрузки допустим.

## Файлы в Data/temp

| Файл | Назначение |
| --- | --- |
| `Data/temp/bitru_backfill_cursor.txt` | Курсор backfill (unix-время) или `finished` |
| `Data/temp/bitru_lastnewtor.txt` | Дата (`dd.MM.yyyy`) самой свежей раздачи последнего `parse`. Старый файл `bitruapi_lastnewtor.txt` переименовывается автоматически |

## Особенности и ограничения

- `.torrent` скачивается только для новых раздач или если изменился заголовок; иначе запись обновляется без дополнительных запросов.
- Раздачи, для которых не удалось скачать `.torrent`, не сохраняются и будут подобраны при следующем проходе.
- Разделы музыки, игр, софта, книг, аудиокниг, изображений и XXX не запрашиваются; из раздела `video` трейлеры, уроки, детское и прочее отбрасываются.

## Диагностика

```bash
curl "http://127.0.0.1:9117/cron/bitru/parse"
curl "http://127.0.0.1:9117/cron/bitru/backfill?pages=5"
curl "http://127.0.0.1:9117/cron/bitru/ParseFromDate?lastnewtor=01.01.2024&pages=3"
cat Data/temp/bitru_backfill_cursor.txt
tail -f Data/log/bitru.log
```
