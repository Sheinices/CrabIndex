# Rutor

![](/img/trackers/rutor.ico)

Rutor (slug `rutor`) - открытый трекер без регистрации, около 550 тысяч раздач. CrabIndex читает листинги `/browse/{page}/{cat}/0/0` по каждой поддерживаемой категории. Магнет-ссылка есть прямо в строке листинга, поэтому страницы раздач не запрашиваются и обход идёт быстро.

Rutor относится к trio-трекерам: частый `parse` берёт свежие страницы, `UpdateTasksParse` раз в сутки обновляет карту страниц, а `ParseAllTask` постепенно обходит весь архив по этой карте.

## Параметры по умолчанию

| Параметр | Значение |
| --- | --- |
| Блок в `init.yaml` | `Rutor` |
| `host` | `http://rutor.info` |
| `alias` | не задан |
| `reqMinute` | `8` (пауза между страницами полного обхода - 7000 мс) |
| Авторизация | не требуется |
| Кодировка | UTF-8 |
| Магнет-ссылки | из листинга |
| Учитывает `disable_trackers` в cron | нет - маршруты `/cron/rutor/*` выполняются даже для отключённого трекера |

## Конфигурация

```yaml
Rutor:
  host: http://rutor.info
  alias: ""        # например, зеркало или адрес .onion
  useproxy: false
  reqMinute: 8
  log: true
```

- `host` - канонический адрес. Из него строятся ссылки на раздачи в FileDB.
- `alias` - адрес, на который фактически уходят HTTP-запросы. Ссылки в базе остаются на `host`.
- `useproxy: true` отправляет запросы через список `proxy`. Правила `globalproxy` (например, `\.onion` → Tor) применяются по шаблону URL независимо от `useproxy`.
- `parseDelay` вычисляется из `reqMinute` (`60 / reqMinute` секунд). Задавать его в YAML бесполезно: при загрузке значение пересчитывается.

Логин и cookie для Rutor не нужны.

## Cron-маршруты

Пути и имена параметров не зависят от регистра: `/cron/rutor/ParseAllTask` и `/cron/rutor/parsealltask` - один и тот же маршрут. Доступ - из локальной сети или с `devkey` (см. [матрицу доступа](../operations/access-matrix.md)).

| Маршрут | Параметры | Ответ | Описание |
| --- | --- | --- | --- |
| `/cron/rutor/parse` | `page` (по умолчанию `0`) | текстовый лог `<cat> - <page> / True` или `False` по каждой категории; `work`, если parse уже идёт | Синхронно разбирает страницу `page` всех категорий |
| `/cron/rutor/UpdateTasksParse` | - | `ok` (запущено в фоне) или `work` | Обновляет карту страниц по верхнему пейджеру первой страницы каждой категории |
| `/cron/rutor/ParseAllTask` | - | `ok` или `work` | Фоновый полный обход ещё не пройденных в текущем цикле страниц карты |
| `/cron/rutor/ParseLatest` | `pages` (по умолчанию `5`) | строки `<cat> - <page>` по успешно разобранным страницам, `ok` или `work` | Разбирает первые `pages` страниц каждой категории из карты и отмечает их пройденными в текущем цикле |

Категории: зарубежные и наши фильмы (1, 5), зарубежные и наши сериалы (4, 16), научно-популярное (12), телевизор (6), мультипликация (7), аниме (10), иностранные релизы (17 - только заголовки с `UKR`), спорт (13), юмор (15). Строки с «трейлер» в названии пропускаются.

## Рекомендуемое расписание

Из `Data/crontab`:

```crontab
# свежие раздачи каждые 15 минут
1,16,31,46 * * * *  /opt/crabindex/Data/run-job.sh rutor-parse http://127.0.0.1:9117/cron/rutor/parse 900

# обновление карты страниц раз в сутки
5 2 * * *  /opt/crabindex/Data/run-job.sh rutor-UpdateTasksParse http://127.0.0.1:9117/cron/rutor/UpdateTasksParse 60

# полный обход (~3,5 ч) дважды в сутки
30 5,17 * * *  /opt/crabindex/Data/run-job.sh rutor-ParseAllTask http://127.0.0.1:9117/cron/rutor/ParseAllTask 60
```

`UpdateTasksParse` и `ParseAllTask` только запускают фоновую работу и сразу отвечают, поэтому им хватает таймаута 60 с. `ParseAllTask` начинает новый круг только когда в текущем цикле не осталось непройденных страниц (pending = 0); иначе продолжает прежний. Незавершённый цикл после рестарта подхватывает общий `/cron/maintenance/ResumeParseAll` (через ~45 с после старта и по cron каждые 15 минут).

## Файлы в Data/temp

| Файл | Содержимое |
| --- | --- |
| `Data/temp/rutor_taskParse.json` | Карта страниц: категория → список страниц с отметками обхода |
| `Data/temp/rutor_parseAllCycle.json` | Состояние текущего цикла `ParseAllTask` (id цикла, время старта, размер карты) |

## Особенности и ограничения

- `UpdateTasksParse` берёт номер последней страницы из живого пейджера и удаляет из карты слоты за ним. Пустой ответ или страница-заглушка карту не обнуляют - категория просто пропускается.
- Страница засчитывается, только если ответ похож на настоящий листинг (есть пейджер или строки раздач). Заглушки Cloudflare и пустые ответы не отмечаются как пройденные.
- `ParseAllTask` и `ParseLatest` уступают часовому `parse`: между страницами они ждут, пока свежий parse не закончится, и выдерживают паузу `parseDelay`.
- `ParseAllTask` отменяется, если 45 минут нет прогресса; `UpdateTasksParse` ограничен 30 минутами. `ParseLatest` не запускается одновременно с `ParseAllTask`/`UpdateTasksParse` (ответ `work`).
- Слот цикла закрывается после успеха или после трёх неудачных попыток подряд; в следующем круге такие страницы пробуются снова.

## Диагностика

```bash
# ручной parse первой страницы
curl "http://127.0.0.1:9117/cron/rutor/parse"

# идущие фоновые задачи и прогресс ParseAllTask
curl "http://127.0.0.1:9117/health/background-jobs"

# состояние циклов ParseAll всех трекеров
curl "http://127.0.0.1:9117/cron/maintenance/ParseAllStatus"

# лог парсера
tail -f /opt/crabindex/Data/log/rutor.log
```

Если запросы не проходят, проверьте `host`/`alias` и [прокси](../configuration/proxy.md). Ответ `401`/`403` на `/cron/` означает, что запрос пришёл не из локальной сети и без `devkey`.
