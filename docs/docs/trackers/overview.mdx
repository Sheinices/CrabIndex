# Обзор трекеров

<TrackerGrid linkPrefix="/trackers/" />


В CrabIndex встроено 25 парсеров трекеров. Каждый парсер складывает раздачи в общую базу FileDB, а все поисковые API ищут уже по ней: к трекерам в момент поиска CrabIndex не обращается. Обход трекеров запускается HTTP-вызовами `/cron/{slug}/...` по расписанию системного cron (см. [Cron](../deployment/cron.md) и [Cron API](../api-reference/cron.md)).

Если у вас нет своих парсеров, базу можно наполнять синхронизацией с `https://sync.crab.rip` или с другим экземпляром CrabIndex (ключ `syncapi`, см. [Синхронизация](../concepts/sync.md) и [Свой сервер синхронизации](../deployment/sync-server.md)). Список `synctrackers` определяет, раздачи каких трекеров принимать при синхронизации.

## Какие трекеры видны в поиске

- Если `synctrackers` не задан, каталог трекеров (`/api/v1.0/trackers`, индексаторы Torznab/Prowlarr) содержит все 25 slug за вычетом `disable_trackers`.
- Если `synctrackers` задан, каталог строится только из этого списка, тоже за вычетом `disable_trackers`.
- Поисковая выдача фильтруется так же. Если `synctrackers` задан, в неё попадают только раздачи перечисленных трекеров. Раздачи трекеров из `disable_trackers` не попадают никогда. Sync API тоже не отдаёт раздачи из `disable_trackers`.
- Slug в этих списках пишите строчными буквами, как в таблице ниже: при фильтрации выдачи регистр учитывается.

:::note[Примечание]
`disable_trackers` **не останавливает** cron большинства трекеров: их маршруты `/cron/{slug}/*` продолжают работать. Ответ `disabled` возвращают только megapeer, selezen, anibelka, korsars и ultradox. У остальных не вызывайте cron отключённого трекера, то есть уберите его строки из crontab.
:::

## Группы трекеров

### Trio: parse, UpdateTasksParse, ParseAllTask

Трекеры rutracker, kinozal, rutor, nnmclub, megapeer, torrentby, toloka, anibelka, korsars и ultradox обходятся тремя задачами:

- **`parse`** - частый (раз в 15-60 минут) обход первых страниц разделов. Отвечает за свежесть базы.
- **`UpdateTasksParse`** - раз в сутки перестраивает карту страниц `Data/temp/{slug}_taskParse.json` по живому пейджеру раздела. Если раздел сократился, лишние страницы удаляются. Пустой ответ считается сбоем загрузки и карту не обнуляет.
- **`ParseAllTask`** - фоновый полный обход карты для обновления сидов, пиров и пропущенных раздач. Прогресс цикла хранится в `Data/temp/{slug}_parseAllCycle.json`. Новый круг начинается, только когда в текущем не осталось непройденных страниц. После перезапуска цикл продолжает `/cron/maintenance/ResumeParseAll`. Страница, которая не загрузилась 3 раза подряд, в текущем цикле пропускается.

Дополнительно у этих трекеров есть **`ParseLatest?pages=5`** - синхронный проход по первым страницам карты. В `Data/crontab` он раз в сутки вызывается для anibelka, korsars и ultradox.

Часовой `parse` имеет приоритет: `ParseAllTask` и `ParseLatest` ждут между страницами, пока закончится `parse` того же трекера.

### API-трекеры

BitRu, Knaben, SubsPlease и AniLiberty получают данные через JSON API, а не разбором HTML. У BitRu и Knaben вместо trio есть `backfill`, который постепенно проходит архив и хранит курсор в `Data/temp`. У SubsPlease для пакетов сезонов есть `ParseShows`.

### Только parse

Остальные трекеры обходятся одним маршрутом `parse`, иногда с ограничением числа страниц (`limit_page`, `parseFrom`/`parseTo`). Небольшие аниме-трекеры (anistar, leproduction, viruseproject, anifilm) достаточно запускать раз в сутки.

## Кодировки

Большинство трекеров отдают UTF-8. Страницы в Windows-1251 CrabIndex перекодирует автоматически: kinozal, nnmclub, megapeer, rudub, baibako, anistar.

## Общие настройки трекера

У каждого трекера в `init.yaml` свой блок (`Rutor`, `Kinozal`, `NNMClub`, `TorrentBy`, `SubsPlease` и т. д.; регистр ключей не важен). Все поля необязательны: если поля нет, берётся значение по умолчанию.

| Поле | Тип | По умолчанию | Описание |
| --- | --- | --- | --- |
| `host` | string | см. таблицу выше | Канонический адрес. От него строятся ссылки на раздачи в FileDB |
| `alias` | string | не задан | Зеркало, onion-адрес или Cloudflare Worker, на который уходят запросы. Поддерживается не всеми трекерами, см. их страницы |
| `useproxy` | bool | `false` | Направлять запросы через `proxy` (см. [Прокси](../configuration/proxy.md)) |
| `reqMinute` | int | `8` (у Megapeer `5`) | Лимит запросов в минуту. Из него вычисляется пауза между страницами |
| `log` | bool | `true` | Писать подробный лог в `Data/log/{slug}.log` (вместе с глобальным `logParsers: true`) |
| `cookie` | string | не задан | Статический cookie сессии |
| `login.u`, `login.p` | string | не заданы | Логин и пароль для автоматического входа |
| `topicFetchAttempts` | int | `5` | Только Rutracker: попытки получить страницу темы через FlareSolverr |

Паузу `parseDelay` задать напрямую нельзя: CrabIndex всегда вычисляет её из `reqMinute` как `60 / reqMinute` секунд. Особые значения: `reqMinute ≥ 60` даёт 1000 мс, `0` или меньше даёт 60 000 мс, `-1` даёт 10 мс. Ключ `parseDelay` в `init.yaml` игнорируется, а в ответах Config API показывается вычисленное значение. Некоторые парсеры (BitRu, Mazepa, Megapeer) используют собственные фиксированные паузы, это указано на их страницах.

Подробнее: [Настройка трекеров](../configuration/trackers.md).
