# Tracks

Модуль **Tracks** узнаёт, какие аудиодорожки и субтитры есть внутри раздачи. Для этого он добавляет торрент в [TorrServer](https://github.com/YouROK/TorrServer), дожидается метаданных и небольшого буфера данных и вызывает у TorrServer `ffprobe` (`/ffp`). Результат сохраняется отдельно от FileDB и попадает в ответы поиска: клиент может показать языки озвучки ещё до скачивания.

Модуль по умолчанию выключен (`tracks: false`).

## Как это работает

```text
FileDB ──► отбор раздач ──► TorrServer (tsuri) ──► /ffp ──► Data/tracks/…json
  ▲          (по возрасту,       добавить торрент,             │
  │           сидам, попыткам)   ждать пиров и буфер           │
  └──────────── счётчик попыток ◄──────────────────────────────┘
```

1. Пять фоновых задач (typetask) периодически обходят FileDB и выбирают раздачи без данных о дорожках:

   | typetask | Какие раздачи | Интервал |
   | --- | --- | --- |
   | 1 | Добавленные за последние сутки | `tracksinterval.task1` минут |
   | 2 | За последний месяц | `tracksinterval.task0` + 2 минуты |
   | 3 | За последний год | `tracksinterval.task0` + 3 минуты |
   | 4 | Старше года, давно не обновлявшиеся | `tracksinterval.task0` + 4 минуты |
   | 5 | Старше года, но обновлённые за последний месяц | `tracksinterval.task0` + 5 минут |

   Для задач 3-5 берутся только раздачи с сидами. При `tracksmod: 1` задачи 3 и 4 не выполняются.

2. Для каждой раздачи выбирается доступный TorrServer из списка `tsuri`, торрент добавляется в категорию `trackscategory`.
3. Модуль ждёт метаданные, пиров (`trackspeerwaittimeout`) и минимальный буфер (`tracksminbufferkb`), выбирает самый крупный видеофайл (пропуская sample, trailer и т. п.) и вызывает `/ffp`.
4. Результат записывается в `Data/tracks/{aa}/{b}/{остаток_infohash}.json`, торрент удаляется из TorrServer.
5. При неудаче у раздачи в FileDB растёт счётчик попыток. После `tracksatempt` неудач раздача исключается из анализа.

Между раздачами выдерживается пауза `tracksdelay` (±10%), одновременно выполняется не больше `tracksconcurrency` анализов. Отдельная задача каждые `tracksorphansweepmin` минут удаляет из TorrServer «осиротевшие» торренты своей категории.

## Включение

```yaml
tracks: true
trackscategory: crabindex-home   # уникальная категория для этого инстанса
tsuri:
  - http://127.0.0.1:8090
```

Все параметры - на странице [Конфигурация Tracks](../configuration/tracks.md).

:::warning[Внимание]
Анализ создаёт реальный торрент-трафик: TorrServer подключается к пирам и скачивает начало файлов. Учитывайте это при выборе сервера и сети.
:::

## Данные в ответах

Найденные дорожки попадают в поле `ffprobe` (список потоков) и `languages` (коды языков аудио) в ответах собственного API и Jackett. Torznab-выдача использует их для обогащения названий при `torznab.enrichTitles: true`. Инстанс-сервер синхронизации также добавляет дорожки в раздачи, которые отдаёт через `/sync/fdb/torrents`.

## Статистика и логи

```bash
# Сводка по Tracks (при openstats: true)
curl "http://localhost:9117/stats/tracks"

# Подробная статистика (локальная сеть или devkey)
curl "http://localhost:9117/dev/TracksStats"
```

Журнал модуля пишется в `Data/log/tracks.log` при `trackslog: true`. Подробные шаги в консоли включает `logging.tracksConsoleDetail: true`.

Экспорт и перенос данных Tracks - эндпоинты `/dev/ExportTracks`, `/dev/ExportTracksStatus`, `/dev/BackfillTracks`, см. [Dev API](../api-reference/dev.md).
